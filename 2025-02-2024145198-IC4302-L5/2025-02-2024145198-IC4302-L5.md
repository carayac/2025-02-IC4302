## Comente 5 factores que afectan el rendimiento de la base de datos

### Optimización de consultas

Es importante gpara un buen rendimiento generar un plan de ejecución o explicación. Esto implica el factor de la optimización de consultas. La base de datos utiliza estadísticas generar  operaciones lógicas para el proceso de recuperación de datos de la memoria o el disco. Esto depende del número de valores esperados: si las estadísticas indican que hay pocos registros, el optimizador elegirá un tipo de acción de recuperación de datos para pocos registros. 
   
El resultado de este proceso es el plan de ejecución o explicación. Muestra operaciones como escaneos, búsquedas y uniones. Algunos motores almacenan planes en caché porque la generación de planes es un proceso que consume muchos recursos de la CPU. 

### Ejecución de consultas

Cuando se ejecuta la consulta, las bases de datos utilizan bloqueos para garantizar la atomicidad de las transacciones. Si otro proceso está actualizando un registro y aún no ha confirmado, la segunda consulta de actualización se bloqueará. Esto significa que la consulta esperará a que se complete la consulta anterior antes de poder ejecutarse. 

El plan de ejecución es el factor más importante para optimizar el rendimiento de las consultas, y un administrador puede influir en él de dos maneras: modificando el índice o actualizando las estadísticas de las columnas, y añadiendo o eliminando índices. Las estadísticas son metadatos sobre la distribución de datos en una columna o índice determinado que ayudan al optimizador a comprender cuántas filas resultarán de una consulta. 

### Ajuste del rendimiento de las consultas con planes de ejecución

Al optimizar el rendimiento de las consultas, lo primero que se debe revisar suele ser el plan de ejecución. Este puede identificar inconsistencias en las estadísticas e indicar dónde podría faltar un índice u otros patrones.

Los optimizadores de consultas utilizan estadísticas para estimar la cardinalidad, o el número de filas, en el resultado de una consulta. Según el número de filas en la estimación de cardinalidad, el optimizador de consultas seleccionará ciertos tipos de operaciones. 


### Cómo las bases de datos consumen recursos del servidor

Los motores de bases de datos gestionan su propia memoria para reducir la utilización de E/S, utilizando cachés para reducir el número de viajes de ida y vuelta al almacenamiento. El tipo de caché más común es la caché de búfer, que almacena los bloques de datos utilizados recientemente. 

Los motores de bases de datos también utilizan memoria para el procesamiento de consultas. Esta memoria se asigna generalmente mediante un cálculo que considera el número de filas por operador y la memoria disponible en el servidor. El procesamiento de consultas es un área donde las estadísticas deficientes pueden afectar el rendimiento del servidor

### Utilización del almacenamiento

Una característica importante del almacenamiento es la velocidad de escritura del registro de transacciones de la base de datos. Para que una transacción se considere completa, debe persistir en el registro de transacciones de la base de datos. Esto significa que el principal limitante del rendimiento es la velocidad con la que se escribe en el registro de transacciones. 

Las copias de seguridad suelen almacenarse en un nivel inferior de almacenamiento con mayor densidad; una copia de seguridad no suele necesitar un almacenamiento rápido de estado sólido. Es frecuente tener al menos tres o cuatro veces la cantidad de almacenamiento bruto asignado para las copias de seguridad. 

## ¿Considera que afectan de igual forma a las bases de datos NoSQL y SQL?
En mi opinión, creo que estos factores no afectan de igual forma a las bases de datos SQL y NoSQL. Creo que es más necesario tomar en cuenta estos factores cuando se está trabajando con bases de datos SQL, debido a que son más rígidas, por lo que necesitarán consultas bien optimizadas. Las bases de datos NoSQL son menos sensibles y tienen más flexibilidad, así que a pesar de no tener las consultas más óptimas tendrán un rendimiento aceptable.

## Explique en qué consiste un antipatrón en bases de datos
Los antipatrones son patrones que se utilizan que en vez de ayudar a resolver el problema de la manera más eficiente, son ineficaces y no son una buena solución. Uno de los antipatrones más comunes en las consultas de bases de datos es el procesamiento fila por fila de grandes conjuntos de datos. Este patrón es común y puede funcionar para bases de datos pequeñas, pero para una base de datos a gran escala va a ser imposible sostenerlo.
