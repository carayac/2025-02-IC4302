## Explique los desafíos que se enfrentan en la construcción de sistemas distribuidos que requieren baja latencia 
Los sistemas distribuidos que requieren baja latencia y escalabilidad enfrentan diferentes desafíos, entre ellos se encuentran:
- **Las consultas se procesan muy lentamente:** Hay muchas maneras de mejorar el rendimiento de las consultas, pero aún así el tiempo de recuperar la información del disco y de procesar la consulta terminará siendo más del deseado, incluso en el mejor de los casos cuando la base de datos está funcionando óptimamente. 
-  **Alto costo de escalar:** La escalabiladad de cualquier tipo de base de datos para un número extremadamente alto de lecturas es muy costosa.  
-  **Simplificar acceso de datos:** Las bases de datos relacionales no son las mejores para accesar los datos. Hay instancias donde es necesario simplificar el proceso de recuperación de datos y mejorar el rendimiento.  

## Explique los tipos de caching. ¿Cuál considera es el más adecuado?
- **Caches integrados en la BD:** La cache es manejada dentro de la base de datos, además de tener capacidades de escritura directa. La base de datos puede actualizar la caché cuando los datos cambian. Nada a nivel de aplicación es necesario para usar la caché. Las desventajas son su tamaño y capacidades. Está limitada a su memoria asignada y no se puede usar para otras acciones. 
- **Caches locales:** Almacena los datos más usados en la aplicación. Permite que la recuperación de datos sea más rápida. La mayor desventaja es que entre las aplicaciones, cada nodo tiene su propio cache. La información en una cache no se puede compartir con las otras. 
- **Caches remotas:** Son instancias separadas que se dedican a almacenar datos en memoria. Puede manejar incluso cientos o miles de solicitudes por segundo por cada nodo. La latencia es muy baja, incluso sub-milisegundo. Son las más adecuadas para sistemas distribuidos.

En mi opinión, considero que la más adecuada es la caché remota, en especial para sistemas distribuidos. Permite mucha más flexibilidad, mientras que las caches integradas y locales tienen muchas limitaciones a la hora de construir aplicaciones con muchos componentes separados, como la mayoría de aplicaciones comerciales en la actualidad.


## Explique las diferencias entre los patrones de caching
La principal diferencia se encuentra en la manera en que la cache llena los datos: ya sea llenarlos en el momento en que se necesitan, o llenarlos antes de que se neecsiten.

|Cache-aside (carga diferida)                         |Write-through                        |
|-------------------------------|-----------------------------|
|Es el patrón más común y utilizado.            |Se implementa al mismo tiempo que la cache-aside, en caso de que haya un cache miss.            | 
|Si se da cache miss y los datos no están en la caché, se consulta la base de datos, y se guardan los datos recuperados de la BD en la cache.             |La cache es llenada en orden contrario, es decir que la cache es llenada inmediatamente haya una actualizacion en la base de datos.          | 
|La desventaja es que debe suceder un cache miss para insertar nuevos datos y puede ser más lento.|Hay más posibilidades que la información que necesitamos esté en la cache, mejorando rendimiento.|  
|La cache solo tiene datos que han sido solicitados, reduciendo costos.|La desventaja es que datos poco usados también pueden estar guardados en la cache.| 


## Explique qué es cache eviction, ¿Por qué es relevante para el rendimiento de un sistema?

El cache eviction se trata de eliminar datos de la cache cuando se llena el máximo espacio disponible para la cache. Los datos que se eliminan dependen de la estrategia que se elija para decidir cuáles son los datos menos relevantes. Por ejemplo, si no se han usado recientemente, si no se han usado frecuentemente, o incluso aleatoriamente. Si es necesario realizar cache evictions frecuentemente, lo mejor es escalar la base de datos.

Es importante para el rendimiento del sistema debido a que necesitamos que la cache tenga los datos más utilizados y actualizados, para disminuir el número de cache miss y consultas a la base de datos que se dan, y así mejorar el tiempo de respuesta y tener un sistema más optimizado.
