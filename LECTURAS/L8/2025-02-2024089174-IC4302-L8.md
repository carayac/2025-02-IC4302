### Explique los conceptos de HA y DR

#####  HA

Representa alta disponibilidad, es utilizado como metrica para medir la resilencia, esto es representado en un porcentaje de tiempo de uso. Es calculado sobre un periodo de tiempo como mes o anio. Se resumen en el tiempo de uso disponible entre el tiempo total.

La alta disponibilidad permite asegurar un rendimiento operacional en caso de algun problema que surja, suele ser aplicado por medio de replicas, isolacion etc

#####  DR

Representa la recuperacion en desastre, es un metodo utilizado para recuperacion de acceso y funcionalidad para la infraestructura despues de un desastre natural o desatre humano. En este caso son politicas que requieren intervencion humana. 

### Explique los conceptos de RPO y RTO

#####  RPO

Es la cantidad de tiempo maxima aceptada desde que paso el ultimo punto de recuperacion de datos. Determina que cual es la perdida de datos considerada entre el ultimo punto de recuperacion y la interrupcion de la base de datos.

#####  RTO

Es el delay maximo aceptado entre la interrupcion y la recuperacion del servicio. Determina el tiempo en que puede estar fuera de servicio la base de datos.

### Comente ¿Cómo funciona la arquitectura de AuroraDB?

La arquitectura de AuroraDB se basa en la alta disponibilidad y la resilencia a fallos, el almacenamiento de Aurora esta distribuido, ademas, utiliza replicas en distintas zonas disponibles. Esto asegura que los datos puedan sobrevivir teniendo diferentes fallas si los nodos pueden fallar. La base de datos almacena en subsistemas con recuperacion independiente de fallos.
Ademas, son escalables automaticamente y ademas recupera automaticamente los problemas en nodos o problemas de escritura.

En una sola región, se puede implementar un clúster de base de datos de Aurora como una configuración Single-AZ (SAZ) o Multi-AZ (MAZ). Y un clúster de base de datos SAZ Aurora se compone de una única instancia de escritor, que acepta solicitudes de lectura y escritura. Por ultimo, Un clúster de base de datos MAZ Aurora se compone de una instancia de base de datos de escritor y al menos una instancias de base de datos de lector.
