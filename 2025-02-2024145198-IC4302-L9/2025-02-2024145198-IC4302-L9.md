# Lectura 9: Spanner

## ¿Cómo funciona la arquitectura de spanner?

Spanner redistribuye automáticamente los datos entre máquinas a medida que cambia la cantidad de datos o el número de servidores, y migra automáticamente los datos entre máquinas para equilibrar la carga y en respuesta a fallos. Spanner está diseñado para escalar a millones de máquinas en cientos de centros de datos y billones de filas de bases de datos. Las aplicaciones pueden usar Spanner para alta disponibilidad, incluso ante desastres naturales de gran magnitud, replicando sus datos dentro de un mismo continente o incluso entre continentes. 
Una implementación de Spanner se denomina universo. Spanner se organiza como un conjunto de zonas, donde cada zona es el equivalente aproximado de una implementación de servidores Bigtable. Una zona tiene un maestro de zona y entre cien y varios miles de servidores Spanner. El maestro de zona asigna datos a los servidores Spanner; los servidores Spanner sirven datos a los clientes. Los clientes utilizan los proxies de ubicación por zona para localizar los servidores Spanner asignados a servir sus datos. El controlador de ubicación se comunica periódicamente con los servidores Spanner para encontrar datos que deban moverse, ya sea para cumplir con las restricciones de replicación actualizadas o para equilibrar la carga. 


## ¿Cómo multi versionamiento en spanner?
Spanner ha evolucionado desde un almacén de clave-valor versionado similar a Bigtable hasta una base de datos multiversión temporal. Los datos se almacenan en tablas semirrelacionales esquematizadas; se versionan y cada versión se marca automáticamente con su hora de confirmación.

En la parte inferior, cada servidor Spanner es responsable de entre 100 y 1000 instancias de una estructura de datos llamada tableta. Una tablet es similar a la abstracción de tablet de Bigtable, ya que implementa un conjunto de asignaciones. A diferencia de Bigtable, Spanner asigna marcas de tiempo a los datos, lo cual es una característica importante que hace que Spanner se asemeje más a una base de datos multiversión que a un almacén clave-valor. El estado de una tablet se almacena en un conjunto de archivos con estructura de árbol B y un registro de escritura anticipada, todo ello en un sistema de archivos distribuido llamado Colossus. Para admitir la replicación, cada servidor Spanner implementa una única máquina de estados Paxos sobre cada tablet. Cada máquina de estados almacena sus metadatos y su registro en su tablet correspondiente. 
Las máquinas de estado de Paxos se utilizan para implementar un conjunto de mapeos replicado de forma consistente. El estado del mapeo clave-valor de cada réplica se almacena en su tablet correspondiente. 
Tanto en Bigtable como en Spanner, se diseñan transacciones de larga duración, cuyo rendimiento es deficiente bajo control de concurrencia optimista en presencia de conflictos. Las operaciones que requieren sincronización, como las operaciones transaccionales, adquieren bloqueos en la tabla de bloqueos; otras operaciones la omiten. 

## ¿En qué consiste el TRUETIME?

Spanner asigna marcas de tiempo de confirmación globalmente significativas a las transacciones, incluso si estas están distribuidas. Dichas marcas de tiempo reflejan el orden de serialización. Además, el orden de serialización garantiza la consistencia externa. El factor clave para estas propiedades es una nueva API TrueTime y su implementación. La API expone directamente la incertidumbre del reloj, y las garantías sobre las marcas de tiempo de Spanner dependen de los límites que proporciona la implementación. Google proporciona una implementación de la API TrueTime. Esta implementación minimiza la incertidumbre. Informar la incertidumbre de forma conservadora es fundamental para la precisión; mantener un límite bajo de incertidumbre es esencial para el rendimiento. 

TrueTime representa explícitamente el tiempo como un TTinterval, que es un intervalo con incertidumbre temporal acotada. Los extremos de un TTinterval son de tipo TTstamp. El método TT.now() devuelve un TTinterval que garantiza contener el tiempo absoluto durante el cual se invocó TT.now(). 

Las referencias de tiempo subyacentes utilizadas por TrueTime son el GPS y los relojes atómicos. TrueTime utiliza dos formas de referencia de tiempo porque presentan diferentes modos de fallo. TrueTime se implementa mediante un conjunto de máquinas maestras de tiempo por centro de datos y un demonio esclavo de tiempo por máquina.
