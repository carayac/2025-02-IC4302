#### 1. De acuerdo con la lectura, identifique y comente 5 factores que afectan el rendimiento de la base de datos.  

**Estadisticas**  
Cuando se ejecuta una consulta, se valida la sintaxis, la existencia de tablas/columnas y los tipos de datos, y con esto, el motor genera un plan de ejecución mediante la optimización de la consulta. Para hacer esto se usan estadísticas sobre los datos y son las que determinan las operaciones lógicas que se usarán para recuperar los datos como escaneos, búsquedas o uniones. Ellas se basan en el número de valores esperados y según eso, puede elegir entre buscar pocos registros o escanear toda la tabla. En SQL Server y Oracle este plan se guarda en caché para que consultas posteriores utilicen el mismo plan.  

**Plan de Ejecución**  
Este se ve influido por índices y estadísticas. Las estadísticas, que se almacenan como histogramas, describen cómo se distribuyen los datos y le dicen al optimizador que hacer: uniones, memoria y operaciones. Realizar buenas estadísticas es muy importante, es importante actualizarlas 

**Locks**  
Los bloqueos durante transacciones pueden afectar el rendimiento, más si son en sistemas con alta actividad o mala gestión de transacciones; por eso las transacciones deben ser lo más cortas posible para reducir riesgos.

**Uso de memoria**  
El motor de base de datos usa su propia memoria para optimizar el rendimiento, reduciendo I/O mediante cachés. Durante el proceso de consultas, se asigna memoria para ordenar y unir filas según estadísticas y memoria disponible, si estas estadísticas son deficientes pueden afectar el rendimiento porque si se asigna mucha memoria que limite consultas simultáneas el motor recurre al disco, más lento.

**Backup Storage**  
Este puede consumir gran volumen, sobre todo en sectores regulados.  Para esto es mejor utilizar almacenamiento de mayor densidad y menor velocidad por que no necesitan almacenamiento de estado sólido rapidos.  Para esto es importante que copias de seguridad deben almacenarse en un dispositivo de almacenamiento separado de los datos y archivos de registro de transacciones, para que en caso de fallo se pueda seguir accediendo.

#### 3. Comente Explique en que consiste un anti-pattern en bases de datos  

Son enfoques ineficaces para resolver problemas.  Uno de los más comunes en las consultas es procesar fila por fila a grandes cantidades de datos porque al hacer esto con tablas que tiene miles y millones de datos, limitan demasiado el rendimiento cuando se realiza un conjunto de operaciones.  La idea es dejar de lado el enfoque basado en filas y usar operaciones basadas en magnitude.  
Otro anti-pattern es tener tipos de datos inconsistentes en el código, lo que provoca conversiones de tipos de datos que pueden afectar el rendimiento de las consultas. Esto puede ocurrir si el lenguaje no utiliza tipos de datos robustos o si no se asignan tipos de datos de la aplicación a la base de datos.
