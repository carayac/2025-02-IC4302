#### 2. Explique los tipos de caching, ¿Cuál considera es el más adecuado?  
<ins>_Databse-integrated caches_<ins>  

Ofrecen una caché integrada que se administra dentro del motor de base de datos y cuenta con capacidades de escritura directa integradas, es decir la base de datos incluye una caché en memoria interna.  La base de datos actualiza su caché automáticamente cuando cambian los datos subyacentes.  
El problema es su tamaño y sus capacidades, ya que suelen estar limitadas a la memoria disponible que le asigna la instancia de la base de datos.

<ins>_Local Caches_<ins>

Este tipo de caching almacena los datos de uso frecuente dentro de la memoria de la aplicación para agilizar la recuperación de datos que son consultados siempre y eliminar el trafico asociado a esa recuperación.  
Una desventaja es que al estar dentro de una aplicación no se puede compartir información con otras cachés por ser nodos individuales y esto afecta en entornos distribuidos porque los nodos pueden estar desactualizados con respecto a otros.  Además, al trabajar localmente, es muy difícil trabajar con aplicaciones de varios servidores y si hay interrupciones, los datos de la caché local se pierden y deben rehidratarse, lo que anula la caché.  
  
<ins>_Remote caches/Side cache_<ins>  
  
Este tipo se basa en instancias independientes dedicadas a almacenar los datos en caché en memoria, almacenadas en servidores especificos para el caso y suelen basarse en key-value NoSQL.  
Una ventaja es que la latencia promedio de una solicitud a una caché remota es de menos de un milisegundo, mucho más rápido que una solicitud a una base de datos en disco.  Además, son ideales para entornos distribuidos porque se conectan a todos los servidores utilizados.  

**¿Cuál puede ser la mas adecuada?**  

La mejor opción puede Side Cache debido a las ventajas que tiene como el hecho de que la latencia es mucho más rapido que una memoria en disco además por el hecho de que tiene la oportunidad de compartir la información con otros nodos permitiendo coherencia entre ellos.  

#### 3. Explique las diferencias entre los patrones de caching.  

<ins>_Cache-aside/lazy loading_<ins>  

Este tipo de patrón se basa en actualizar la caché después de solicictar la data.  Por ejemplo, si la aplicación tiene que leer información de la base de datos, primero se revisa la caché para saber si la data está disponible.  Si la información está disponible entonces se retorna y se emite al solicitante pero si la data no está disponible entonces se consulta a la base de datos, la caché se actualiza con nueva información y se emite al solicitante.  
La ventaja de este tipo es que la aché tiene solo la información que se solciita haciendo su tamaño algo rentable.

<ins>_Write-Through_<ins>  

Este tipo se patrón se basa en actualizar inmediatamente la caché despues que la base de datos se actualice, entonces si el procesos de aplicación, lote o backend actualiza la base de datos inmediatamente lo hace en caché también.  
La ventaja es que los datos siempre están en caché esto permite mejor rendimiento en la aplicación y mejor experiencia de usuario, pero al almacenarse ahí siempre hace que sea costosa.  


#### 4. Explique que es cache eviction, ¿Por qué es relevante para el rendimiento de un sistema?  

Caché Evicton se refiere a cuando la memoria caché se llena, está sobrecargada o supera el limite de memoria máxima permitido y se necesita liberar espacio para guardar nuevos datos.  
Se mencionan diferentes politicas a seguir para desalojar los datos y es vital elegir la adecuada para no cometer errores dd eliminar datos importantes por ejemplo.  El cache eviction es importante porque al estar lleno puede que las cosnultas a la caché duren más tiempo y más bien lo que se busca es lo contrario.  Además, si se presentan mcuhos evictons significa que debe escalar verticalmente u horizontalmete su clúster (conseguir nodos con mayor consumo de memoria) para guardar datos adicionales.
