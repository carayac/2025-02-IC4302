# Lectura 8: Amazon Aurora


## Explique los conceptos de HA y DR
El concepto de HA corresponde a High Availability (Alta disponibilidad) y el de DR a Disaster Recovery (Recuperación ante desastres). 

**Alta disponibilidad**: La disponibilidad mide que tan resiliente es un servicio (cuánto aguanta sin fallos). Esta disponibilidad de una carga de trabajo se mide como el porcentaje de tiempo que el servicio está disponible y se puede usar. Este porcentaje se mide en un tiempo dado, por ejemplo, está disponible 99.99% del tiempo en un mes. 
Las bases de datos de alta disponibilidad pueden garantizar ese nivel determinado de rendimiento, incluso ante fallos, pudiendo resolver porblemas de manera automática sin intervención manual. La alta disponibilidad se logra creando una o varias replicas de bases de datos independientes que toman el control cuando una falla.

**Recuperación ante desastres**: 
Independientemente de la alta disponibilidad, la recuperación de desastre también aporta a la resiliencia de un sistema. La recuperación ante desastres se refiere al método que utiliza una organización para recuperar el acceso y la funcionalidad del sistema tras un desastre, puede ser un desastre natural o un desastre causado por humanos. Estos métodos sí pueden llegar a necesitar intervención manual, como ejecutar scripts, modificar endpoints y expandir infraestructura. 


## Explique los conceptos de RPO y RTO
En la recuperación de desastres, dos conceptos importantes son el Objetivo de Tiempo de Recuperación (RTO) y el Objetivo de Punto de Recuperación (RPO). El RTO y el RPO se basan en los requisitos que tiene un sistema específico. Estas medidas dependerán de la aplicación en cuestión y la carga de trabajo, ya que puede variar mucho incluso dentro de la misma organización.  
El RPO es el tiempo máximo aceptable desde el último punto de recuperación de datos. Esto determina qué se considera una pérdida de datos aceptable entre el último punto de recuperación y la interrupción de la base de datos. Por ejemplo, si define un RPO de 15 minutos, en caso de desastre, podría perder hasta 15 minutos de datos, pero no más. 
El RTO es el retraso máximo aceptable entre la interrupción de la base de datos y la restauración del servicio. Esto determina qué se considera un intervalo de tiempo aceptable cuando la base de datos no está disponible. Por ejemplo, si determina que el RTO de su aplicación es de 5 minutos, su estrategia de recuperación ante desastres debería permitir que la aplicación vuelva al servicio en un máximo de 5 minutos.

## ¿Cómo funciona la arquitectura de AuroraDB?
La arquitectura de Aurora está diseñada desde cero para ofrecer alta disponibilidad y resiliencia ante fallos. El sistema de almacenamiento de Aurora es distribuido. Se encarga de replicar cada escritura de seis maneras en distintas availability zones. Esto garantiza que aunque ocurra un fallo total en una availability zone, los datos no se pierdan. Esta arquitectura de almacenamiento distribuido también puede escalar y autorrepararse automáticamente ante problemas como fallos de nodos, y completar las escrituras faltantes mediante un protocolo punto a punto entre nodos de almacenamiento.


Los recursos computacionales están desacoplados de su almacenamiento, lo que permite que los subsistemas de computación y almacenamiento funcionen y se recuperen de manera independiente ante fallos. 


Un clúster de base de datos MAZ Aurora se compone de una instancia de base de datos de escritura y al menos una (y hasta 15) instancias de base de datos de lectura. Una instancia de base de datos de lectura actúa como una réplica de lectura con bajo retardo y solo acepta solicitudes de lectura. 
Cuando se utiliza una arquitectura MAZ, Aurora detecta automáticamente cualquier interrupción en la instancia de la base de datos de escritor. Si tiene más de una instancia de la base de datos de lector, se puede asignar un orden de prioridad a las instancias de la base de datos de lector. La instancia de la base de datos de lector con la prioridad más alta se elige como el primer destino de conmutación por error. Tras una conmutación por error exitosa, las aplicaciones que intentan reconectarse mediante el punto de conexión del escritor se redirigen automáticamente a la instancia de la base de datos de escritor recién promovida. 


Aurora también admite el uso de un contenedor de conectividad avanzada de bases de datos Java (JDBC) en el controlador JDBC de AWS. Este contenedor complementa el JDBC de código abierto existente. 

Aurora también ofrece Amazon Aurora Global Database, que permite que un clúster de base de datos Aurora abarque varias regiones. 

Aurora también ofrece Implementaciones Azul/Verde administradas que pueden utilizarse para reducir el tiempo de inactividad en operaciones disruptivas, como actualizaciones de bases de datos de versiones principales y secundarias, pruebas de nuevas funciones de bases de datos y aplicaciones, y mantenimiento o cambios de esquemas.
