# Lectura 1: Overview of No SQL Databases

Comente las diferencias, ventajas y desventajas de los siguientes tipos de bases de datos no SQL.



## Key-Value Pairs

**Características importantes**

- Los datos se alamacenan en parejas llave-valor.
- Las llaves no tienen que ser integer, pueden ser cualquier tipo de dato.
- Es importante usar una estrategia de nombramiento de llaves eficiente.


**Ventajas** 

- Es simple: Da flexibilidad al no imponer una estructura de datos.
- Alto rendimiento y velocidad: Capacidad caché de mantener los datos más usados en memoria y accesarla rápidamente para mejor rendimiento.
- Experiencia de usuario personalizada: Permite seguir la huella digital.
- Respuesta de aplicación rápida: Recuperación de datos inmediata. 
- Portabilidad y costo: las empresas pueden variar su producto a traves de diferentes SO manteniendo la funcionalidad.
- Escalabilidad: Aguanta una gran cantidad de datos.


**Desventajas**

- Solo se puede recuperar información por medio de llaves. 
- Actualizar y obtener una parte específica de la información es mas tardado que en SQL.
- Cuando hay muchas transacciones podría no mantenerse la consistencia.
- Mantener una cantidad muy grande de llaves únicas puede ser complicado sin el algoritmo correcto.




##  Document Oriented

**Características Importantes**

- El documento es como una fila en SQL.
- Esta BD tambien consiste de parejas llave-valor solo que los valores son más complicados, ya sea estructurados o semi estructurados.
- Una colección puede tener varios documentos, dentro de los cuales puede haber índices secundarios que pueden ser accesados. 
- Cada documento tiene una llave.


**Ventajas**

- Puede guardar distintos formatos (soporta json y xml,  integers, chains, booleans y data arrays).
- Aunque la arquitectura de cada documento es consistente, los campos dentro de cada documento son únicos.
- No hay espacios en blanco, pues no es requerido que diferentes documentos tengan la misma información.
- No hay que mantener integridad relacional.
- Se pueden agregar nuevos campos en nuevas versiones de la BD.
- Son rápidas, fáciles de diseñar e intuituvas.
- Tiene indexación flexible.


**Desventajas**

- Puede ser difÍcil crear relaciones entre documentos.
- Las referencias no funcionan muy bien.
- Puede ser difícil manejar muchos documentos
- Las operaciones de agregación podrían no ser exactas.





## Wide Column

**Características Importantes**

- A diferencia de los dos tipos de BD anteriores, estas BD se agrupan familias de columnas.
- Es útil para el análisis de datos extensivo.
- Se puede utilizar para el análisis de datos históricos.


**Ventajas**

- Funciona con datos organizados y semi estructurados.
- Actualizar los datos es fácil.
- La exploración y búsqueda de datos es sencilla.
- Es más intuitiva y puede haber una mejor compresión.
- Son buenas a la hora de particionar datos.
- Son buenas al realizar operaciones de agregación.
- Es posible cargar columnas en paralelo.
- Tiene una buena escalabilidad.


**Desventajas**

- Las operaciones de insertar y eliminar para un solo record son muy lentas.
- Actualizar una tupla específica es muy costoso.
- Un record que está unido en varias columnas es muy lento a la hora de ser buscado.
- Si hay muchas operaciones de lectura y escritura no es bueno para OLTP.




## Graph

**Características Importantes**

- Guarda datos en nodos, esquinas, y atributos que permiten busqueda semántica.
- Funciona para guardar datos que están muy relacionados.
- Cada nodo es inmediatamente accesible (index free adjacency)
- El almacenamiento lo sustenta todo
- Diseñado para el almacenamiento de grafos.


**Ventajas**

- Tiene buenas capacidades de consulta.
- Tiene un motor de procesamiento eficiente.
- Es muy bueno para tratar datos muy relacionados.
- Tiene capacidades aditivas de nuevas conexiones.


**Desventajas**

- Las estructuras de datos y las restricciones son muy limitadas. 
- Es difícil soportar escalabilidad horizontal.
- En la vida real los gráficos son muy dinámicos.
